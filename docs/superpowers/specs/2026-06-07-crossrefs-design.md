# Cross-references in Calepin — Design

Date: 2026-06-07
Status: approved (pending written-spec review)

## Problem

Cross-referencing chunk output in Calepin is ad hoc and incomplete:

- The `label:` argument does three unrelated jobs at once: the `results.json`
  key, the figure artifact filename stem, and (only sometimes) the Typst
  cross-reference label.
- A real Typst `<label>` is emitted only by `_attach-label`, and only when a
  chunk produces an image **and** carries a `fig-caption`. So captionless
  figures, tables, code listings, and plotless chunks are not referenceable.
- Auto labels (`chunk-N`) are never attached to anything, so `@chunk-N` never
  resolves.
- A label written after a fence (`` ```r ... ```<fig-x> ``) cannot be
  referenced at all: Typst freezes the label to the `raw` source element, and
  `@fig-x` errors with "cannot reference raw directly". This was verified five
  ways against typst 0.14.2, including wrapping the original element in a
  `figure` (`figure(it, kind: image)` and `figure(it, kind: raw)`) — still
  frozen as `raw`.
- A fenced chunk has no way to carry a stable custom label: `#| label:` is
  rejected by the qmd-header parser, and the chunk label is always `chunk-N`.

## Goals

- Quarto-compatible cross-reference UX: `@fig-x`, `@tbl-x`, `@lst-x`.
- One coherent notion of "the chunk's label(s)", three ways to supply it, one
  prefix-routing rule for all of them.
- Reference the plot OR the code (or both) of the same chunk without deciding
  up front.
- Be strict: unprefixed labels, channel conflicts, and missing targets are
  errors, not silent degradation.

## Non-goals

- Rewriting Calepin into a Typst renderer. Calepin keeps driving the real
  `typst` binary.
- Cross-document references / a global reference index.
- Numbering schemes beyond Typst's native per-`kind` figure counters.

## The label model

### Prefix routing

A label's prefix selects the element it attaches to:

| Prefix  | Target element         | Typst wrapper                         |
| ------- | ---------------------- | ------------------------------------- |
| `fig-`  | figure / plot          | `figure(image, kind: image)`          |
| `tbl-`  | table output           | `figure(content, kind: table)`        |
| `lst-`  | code listing (echo)    | `figure(raw, kind: raw)`              |

Recognized prefixes are fixed (`fig-`, `tbl-`, `lst-`). The prefix set lives in
one place so it is easy to extend later.

### `label:` accepts a string or a list

```typ
#calepin.chunk(label: "fig-plot")[...]                  // single
#calepin.chunk(label: ("fig-plot", "lst-code"))[...]    // multiple kinds
```

- Each entry is routed by its own prefix.
- Entries must be of **distinct kinds**. Two `fig-` entries in one list is an
  error (panels are handled by sub-label derivation, below).
- A single string is the common case and is sugar for a one-element list.

### Strict: unprefixed labels are errors

Any user-supplied label without a recognized prefix is an error:

```
chunk error: label `myplot` has no recognized cross-reference prefix
  (expected one of: fig-, tbl-, lst-)
```

The internal auto id `chunk-N` is generated by Calepin, is never a
cross-reference target, and is exempt.

### Captions are per kind

Captions pair to their label by prefix:

- `fig-cap` / `fig-caption` -> the `fig-` figure
- `tbl-cap` / `tbl-caption` -> the `tbl-` figure
- `lst-cap` / `lst-caption` -> the `lst-` listing

A `fig-`/`tbl-`/`lst-` label makes its element a referenceable `figure` even
without a caption (the caption is optional; the label forces the wrapper).

## Input channels and precedence

Three channels supply labels; all feed the same prefix-routed slot:

1. Function argument: `calepin.chunk(label: ...)`.
2. qmd header: `#| label: fig-x` or `#| label: [fig-x, lst-x]`. (The header
   parser already parses `[a, b]` lists; `label` must be added to the allowed
   header options and wired to the chunk's label slot.)
3. Harvested Typst fence label: `` ```r ... ```<fig-x> `` (auto-run fenced
   chunks). The raw node's `.label` field is visible to `typst query`
   (verified), so Calepin reads it during the query pass.

### Conflict = error

At most one channel may supply labels for a given chunk. Supplying more than
one (e.g. a `label:` arg and a fence `<...>`, or a `label:` arg and a
`#| label:` header) is an error naming the chunk. Auto `chunk-N` is assigned
only when **zero** user channels are present.

## Internal id vs cross-reference labels

Because `label:` is now a list of cross-reference names, it can no longer
double as the single internal key. Split them:

- **Internal id** — keys `results.json` and the figure artifact filename stem.
  Derived from the **primary (first) label** when present, else auto `chunk-N`.
  Keeps artifacts readable (`fig-plot-1.svg`).
- **Cross-reference labels** — the routed list, carried alongside the id.

## Panels and sub-labels

A single `fig-x` on a multi-plot chunk references the whole figure/grid, and
derives `fig-x-1`, `fig-x-2`, ... for individual panels (mirrors the existing
artifact filenames `fig-diagnostics-2.svg`). Sub-labels are attached to the
per-panel cells in `_render-image-grid`. List entries are for distinct kinds,
never for panels.

## Missing target = error

If a routed label has no element to attach to, error at preprocess/render time:

- `fig-x` but the chunk produced no image.
- `lst-x` but `echo` is false (no listing rendered).
- `tbl-x` but the chunk produced no table/typst output.

The error names the chunk and the offending label.

## Implementation architecture

### Rust side (query / preprocess)

- `query.rs`: harvest the raw block `.label`; parse `label`/`lst-label`-style
  options; validate prefixes (strict), list shape (distinct kinds), and
  channel conflicts; assign internal id (primary label or `chunk-N`); attach
  the routed label list and an ordinal to each `ChunkSpec`.
- `chunk_options.rs`: add `label` (and the per-kind caption keys) to the
  allowed qmd-header options; reuse the existing list parser.
- `model.rs`: `ChunkResultDocument` carries the cross-reference label list and
  routing keyed by internal id; the `results.json` map is keyed by internal id.
- `execute.rs`: figure artifact filename stem uses the internal id.
- Normalized source / strip step (new module — the empty `process.rs` is the
  intended home): produce a `.calepin/<stem>/` copy of the source with trailing
  `<...>` fence labels removed so Typst no longer binds them to `raw`. Removal
  is the last token on the closing-fence line, so **line numbers are
  preserved** in diagnostics. The render-pass wrapper `#include`s this
  normalized copy instead of the literal file.

### Label plumbing (chosen approach)

Harvested fence labels are stripped from the source, so the runtime cannot
recompute them. The runtime obtains each fenced chunk's label list and routing
from `results.json`, matched by the chunk's ordinal/internal id as it walks the
document in order (the same ordering Calepin already relies on). Explicit
`calepin.chunk(label: ...)` calls still read the label from the argument
directly. This avoids wrapping bare fences into function calls (which would
shift line numbers).

### Typst runtime side

- `state.typ` / `render.typ`: a routing helper maps a label list to targets by
  prefix and attaches each via `label(...)`.
  - `fig-` -> the `figure(image)` (force the `figure` wrapper even without a
    caption).
  - `lst-` -> wrap the echo in `figure(kind: raw, supplement: [Listing])`.
  - `tbl-` -> wrap typst/table output in `figure(kind: table)`.
- `_render-image-grid`: attach derived `-N` sub-labels to panel cells.
- HTML and paged targets both supported (HTML uses native counters as in the
  existing `_html-captioned-figure`).

### Risk: `tbl-` and tinytable

Tinytable's `print('typst')` may already emit a `figure`. Wrapping again would
nest figures. During implementation, verify against tinytable and, if it
already emits a figure, attach the label to that figure rather than wrapping.
This is the highest-risk routing path and gets a dedicated behavior test.

## Error catalog (strict mode)

1. Unprefixed user label.
2. Two list entries of the same kind.
3. More than one labeling channel for one chunk.
4. Routed label with no matching target element.

Each error names the chunk (by internal id or source location) and the label.

## Testing (behavior-focused)

Per repo convention, assert on observable behavior, not generated source or
byte layout. Integration tests shell out to `typst` and skip when absent.

- `@fig-x` resolves for a captioned and a captionless plotting chunk.
- `@lst-x` resolves to a code listing; errors when `echo: false`.
- `@tbl-x` resolves for a tinytable chunk without nested figures.
- Harvested `` ```r...```<fig-x> `` resolves to `@fig-x`; the stripped source
  preserves line numbers in a forced error.
- `label: ("fig-x", "lst-x")` yields both `@fig-x` and `@lst-x`.
- Panel sub-labels `@fig-x-2` resolve in a multi-plot grid.
- Strict errors fire: unprefixed label, duplicate kind, channel conflict,
  missing target.

## Open items for the plan

- Exact ordinal/id matching contract between Rust `results.json` and the
  runtime walk (must be order-stable across query and render passes).
- Whether `#| label:` lines remain visible in the echoed listing (existing
  header-echo behavior is out of scope but should not regress).
- Tinytable figure-nesting resolution (see Risk above).
